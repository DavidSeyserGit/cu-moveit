# cu-moveit 0.5.0

Breaking API simplification across the whole workspace — same capabilities,
one obvious way to use each. Pre-1.0, so no compatibility shims; the full
mapping is in [`docs/migration-0.5.md`](../migration-0.5.md) and the rules
behind it in [`docs/api-conventions.md`](docs/api-conventions.md).

## The new shape

- **One params struct per thing.** Every algorithm, task, and bridge has a
  single `Cu<Thing>Params` (serde, `deny_unknown_fields`, one `Default`,
  `validate()`). A task's RON `config:` block *is* that struct — read with
  `deserialize_into`, no key-by-key parsing, no unit suffixes in key names
  (values are SI, types carry units).
- **One constructor shape.** `from_params(required…, params) -> CuResult<Self>`
  for tasks/algorithms, validating `new(...) -> CuResult` for data types,
  `with_*` builders for optional parts. `new_with_*` / `try_new` /
  `from_meters`-style variants are gone.
- **One import path per item.** Modules are private; everything is imported
  from the crate root. No crate re-exports another crate's types
  (`CuJointStatePayload`/`CuRobotStatus` now live solely in `cu-kinematics`).
- **Units everywhere.** Accelerations and jerks are typed
  (`CuJointAcceleration`/`CuJointJerk`); RON timing limits use typed values
  instead of bare `f64` arrays.

## Per crate

- `cu-kinematics`: `CuIkParams`/`CuDiffIkParams`, preset-or-inline chain
  specs (`"chain": "igus_rebel"`), `from_params` tasks.
- `cu-collision`: borrowed zero-copy `CuCollisionEnv` replaces
  `CuCollisionWorld`; one check path covers robot, obstacles, attached
  shapes, and exclusions; adjacent-link skipping is explicit and uniform.
- `cu-trajectory`: one `parameterize(...)` entry with `CuTimingParams` +
  `CuTimingOverrides`, one `CuTimingStatus`; payloads carry their own
  interpolation; follower honors it unless overridden.
- `cu-robot-description`: params-object imports (`CuUrdfImport`/`CuSrdfImport`),
  `chain()`/`collision_model()`/`into_parts()` accessors.
- `cu-motion-planning` / `cu-joint-rrt-star`: uniform planner shape
  (`CuJoint<Algo>` + `CuJoint<Algo>Params` + `CuJoint<Algo>Task`),
  `CuJointPlannerTask::from_planner`/`from_params`, one planner node config.
- `cu-controller`: one `CuControllerParams` (`mode`, `tracking_error_limit`,
  `state_timeout: Option<Time>`, `rate_limit: Option<CuRateLimit>`,
  `effort_gains: CuEffortGains`); effort defaults are now the stable
  20.0 / 0.8 (the previous 80 / 17.9 diverged at the 50 Hz bridge rate).
- `cu-mujoco-sim`: one `CuMujocoSimParams` (`read_timeout: Time`); command
  line carries `q`/`qd`/`effort`/`mode`.
- `cu-io`: `CuGripperParams` with typed `Time` durations.

## Playground (local, git-excluded)

`sim_demo` and `exec_app` migrated to the new APIs — the demo names library
tasks directly in RON (no app-local wrappers) and still closes the loop:
`{"success":true,"final_error_rad":0.009167,"cycles":54}`. The Studio
executes through follower + controller in position and effort modes.

Workspace version 0.5.0, one shared version as usual; consume via git
dependency on the `v0.5.0` tag.
